==============================================================================
 SANKU AI POSE STUDIO  -  HOW IT WORKS            (build 1.3.4, Blender 5.1)
==============================================================================

1. WHAT IT DOES
------------------------------------------------------------------------------
You give it one photo of a person. It finds the person, reads 133 body / hand /
face keypoints, works out a real 3D depth for every joint, and then rotates the
bones of a Rigify armature so the character copies the pose in the photo.

    photo -> person box -> 133 keypoints -> depth map -> 3D joints
          -> bone rotations -> Pose Mode pose on your Rigify rig

Everything runs locally on your machine (CPU, or GPU through DirectML / CUDA
when available). Nothing is uploaded; the internet is only used once to
download the add-on's dependencies and model files.


2. INSTALL
------------------------------------------------------------------------------
1. Blender > Edit > Preferences > Add-ons > (dropdown arrow, top right)
   > Install from Disk... > pick the ZIP (do not extract it first).
2. Tick "Sanku AI Pose Studio".
3. Open the 3D Viewport, press N, open the "Sanku AI Pose Studio" tab.

First-time setup (needs internet, done once):
   a) "Install Dependencies"  - installs onnxruntime into the add-on's own data
      folder using Blender's bundled Python (Blender itself is not modified).
      If Blender's Python has no pip, the add-on now bootstraps it (ensurepip).
   b) "Download Models"       - downloads (about 340 MB for DWPose + the depth
      model): yolox_l.onnx (person detector), dw-ll_ucoco_384.onnx (pose model)
      and a Depth Anything V2 Small model. A mirror is tried if the first
      address is unreachable.
   Already have the files (e.g. from ComfyUI)? Use "Import from Local Folder"
   / "Import Depth Model" in the add-on preferences instead of downloading.
   ESC cancels a running download or installation.


3. USING THE PANEL (top to bottom)
------------------------------------------------------------------------------
The top of the panel shows whether dependencies, models and the depth model are
ready. Then four numbered sections:

1. Input Image
   - Image Source: an image file on disk, or an image already loaded in Blender.
   - Person Index: which person to use if there are several (0 = the largest).
   - Detect Pose: runs the detector + pose model (about 1-5 s on CPU). A preview
     with the drawn skeleton can be shown in the Image Editor.

2. Target Armature
   - Pick your armature (or use the active one). No rig yet?
       New Metarig      adds Rigify's human metarig,
       Generate Rig     turns a metarig into a Rigify control rig.
   - Auto-Match Bones   finds the right bone for every role (spine, clavicle,
     upper arm, forearm, hand, thigh, shin, foot, toe, fingers ...). The
     "Bone Mapping" sub-panel lists every role; you can change any bone by hand.
   - Clear Pose         resets the bones the add-on writes to.

3. Pose Solving
   - Person Facing: front / back / facing image-left / facing image-right.
   - Depth Source:  Depth model (recommended), Bone-length solve (old method,
     guesses front/back), or Flat (no depth).
   - Perspective Strength: virtual focal length. Raise it if the pose looks too
     flat, lower it if it looks exaggerated.
   - Flip Depth Direction: only tick it if the whole pose came out reversed
     front-to-back. The depth preview and the panel text tell you when the fit
     and the "person is closer than the background" check disagree (marked *).
   - Swap Left/Right: only if the detector mixed up the sides.
   - Estimate Bone Twist + Twist Strength: aligns bone roll using shoulder /
     hip / elbow-knee bend axes so arms and head do not get twisted.
   - Scale Fine-Tune, Write Fingers, Hand Along Forearm (0-1): pull the hand
     towards the forearm direction; finger keypoints are noisy so default is 0.5.
   - View Depth Map / Depth Preview Window: false-colour depth (near = blue,
     far = red) plus statistics, to check the depth is sensible. The separate
     window needs a Python that has tkinter (set it in the preferences if the
     add-on cannot find one).

4. Write Pose
   - Write Root Translation, Ground Align: optional body position / height.
   - Limb Write Mode:
       IK Controls (default, Rigify's default state): the pose is written
         straight into hand_ik / foot_ik / upper_arm_ik / thigh_ik, and the FK
         chain gets the same pose so nothing is lost if you switch to FK later.
       FK Bones: the pose stays on the FK bones and IK_FK is set to 1.
   - Sync Control Display: shows only the controls that are active. Click it
     after you drag Rigify's IK-FK slider yourself.
   - Insert Keyframe, then "Apply to Armature" - writes the pose on the current
     frame. A one-line report says which solver was used and what was written.

Add-on preferences also hold: backend (auto / onnxruntime / OpenCV DNN),
inference device (auto / CPU / DirectML / CUDA), depth model variant (fp32 about
95 MB, fp16 about 48 MB, int8 about 27 MB), local model folders and the Python
used for the preview window.


4. WHAT HAPPENS INSIDE (module map)
------------------------------------------------------------------------------
__init__.py       registers everything; bl_info.
props.py          scene settings + add-on preferences, model path resolution.
ui.py             the N-panel and the bone-mapping list.
operators.py      all buttons. Long jobs (install, download, detect) run in a
                  background thread; a modal timer collects their log / status /
                  progress messages so Blender stays responsive-looking.
deps.py           pip install, ensurepip, model download (with mirror fallback,
                  size check, cancel support), local model import.
dwpose.py         YOLOX-L person detector + DWPose (SimCC) pose model, with
                  onnxruntime or OpenCV DNN back-ends. 133 COCO-WholeBody points.
coco.py           keypoint index tables (body, feet, 68-point face, 21+21 hand).
depth.py          Depth Anything V2 ONNX: relative depth map + pixel sampling.
imops.py          small numpy image toolkit (resize, warp, NMS, drawing).
reconstruction.py the maths: 2D keypoints + depth -> 3D joints in armature scale
                  (see section 5).
rigify_map.py     role -> bone-name mapping, reads rest-pose lengths / axes.
retarget.py       turns 3D joints into pose-bone matrices and writes them.
rigify_limbs.py   Rigify IK/FK bridge: reads the generated UI script, switches
                  limbs, snaps FK->IK, syncs bone-collection visibility.
depth_view.py     standalone Tk window for the depth preview (no Blender needed).
utils.py          paths, logging, reading Blender images, finding Python.

5. THE POSE MATHS IN SHORT
------------------------------------------------------------------------------
- A depth model only gives RELATIVE depth (true depth = alpha * d + beta).
- The add-on fits alpha and beta once, globally, so that the 3D length of every
  bone segment in the photo equals the bone length of YOUR armature
  (Gauss-Newton least squares with a perspective camera). Because of perspective
  "who is nearer the camera" changes the pixel scale, so front/back is solved
  from the pixels instead of guessed (no more "elbow always bends backwards").
- If the depth map is missing, or the fit is clearly bad, it falls back to the
  old orthographic bone-length solve and says so in the status line.
- When bone lengths cannot tell front from back (frontal standing photo), a
  physical rule decides: the person is closer to the camera than the background.
- Head and neck direction are voted from the 68 face points (eye corners, brows,
  mouth, jaw); the ears are only used when they agree with the face.
- Each bone gets a rotation made of "aim" (rest direction -> target direction)
  plus "twist" (roll aligned to a reference axis).
- In IK mode the pose is written into the IK controls using the same maths as
  Rigify's own "IK->FK" button, then checked against the DEF bones (joint error
  under 2 cm and 10 degrees). Any limb that fails the check automatically falls
  back to: switch to FK, write FK, call Rigify's IK->FK snap.


6. TROUBLESHOOTING
------------------------------------------------------------------------------
- "Install Dependencies" fails: check the log in the panel (a Log sub-panel
  shows pip output). Typical causes: no internet, firewall, or no onnxruntime
  wheel for your Python version. You can choose OpenCV instead in the
  preferences. A folder that is not writable is handled by the --user fallback.
- Pose is mirrored front-to-back: tick Flip Depth Direction and Apply again.
- Left and right are swapped: tick Swap Left/Right, or set Person Facing.
- Arms / head twisted: lower Twist Strength or untick Estimate Bone Twist.
- Nothing moves with a Rigify rig: make sure Limb Write Mode matches the
  IK/FK state, then press Sync Control Display.
- Hands look odd: raise Hand Along Forearm, or leave Write Fingers off.
- Depth preview window does not open: set "Preview Window Interpreter" in the
  preferences to a system python that includes tkinter.
- Everything is stored in the add-on data folder shown in the preferences
  (Dependency folder / Model folder). Deleting it resets the add-on.


7. WHAT CHANGED IN THIS BUILD (1.3.3 -> 1.3.4)
------------------------------------------------------------------------------
LANGUAGE
- All Chinese text (UI labels, tooltips, messages, logs, comments, docstrings,
  LICENSE note) was translated to English. Code logic was not changed by the
  translation; this was verified by comparing the syntax trees of every file
  with the original (only strings and comments differ, format codes unchanged).

BUG FIXES
 1. Log / status / progress messages from background jobs were silently dropped
    (worker threads sent one tuple, the receiver expected two arguments). The
    pip output, download progress bar and status text now actually appear.
 2. Bone-list labels for left/right roles never resolved (showed raw ids like
    "shoulder.L"); they now show "Clavicle L", "Hand R", etc.
 3. Dependency install failed on a fresh Blender whose Python has no pip; it now
    bootstraps pip with ensurepip (with a --user fallback).
 4. ESC could not stop a running pip install, which could lock Blender's UI
    until pip finished; it now terminates pip. A cancel() handler was also added
    for jobs aborted from outside (closing the window / loading a file).
 5. A truncated model download was accepted as a finished model file; the size
    is now checked and half-written .part files are removed.
 6. Reading a Blender image reset its colour space to sRGB even if it had been
    something else; the original colour space is restored.
 7. Python lookup used by pip now prefers sys.executable and knows the macOS
    app-bundle layout; "Open folder" works on macOS.
 8. Rigify: bone-collection lookup now also finds nested collections
    (collections_all), and an empty limb-spec result is no longer cached forever
    while a rig is still being generated.
 9. Removed "from __future__ import annotations" from the files that declare
    Blender properties (props.py, operators.py) so property annotations are
    always real Blender properties.

OPTIMIZATIONS
- The dependency check shown in the panel is cached for 3 s instead of
  re-importing onnxruntime / OpenCV on every redraw.
- Cleaner package: the ZIP holds a single add-on folder (Blender installs it
  without scattering README / LICENSE files into the add-ons directory),
  no __pycache__, maximum compression.
- Version bumped to 1.3.4.

NOT VERIFIED
- The code could not be run inside a real Blender session while preparing this
  build. It was compiled, import-tested against stubbed Blender modules and the
  non-Blender parts (image ops, downloader, message queue, labels) were executed.
  Please test once on a throw-away scene.
